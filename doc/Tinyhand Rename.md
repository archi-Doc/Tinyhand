# Tinyhand Rename

Public API renames in **Tinyhand** and **TinyhandGenerator** after version 0.146.0.
All renames are breaking; no compatibility aliases are provided. Behavior and wire format are unchanged. Diagnostic IDs (`TGxxx`) are unchanged.

## How to migrate

1. **User code**: update attribute arguments (`PropertyName`, `AlternateKey`, `LockMemberName`) and any direct calls listed below.
2. **Source generators that emit Tinyhand calls** (e.g. ValueLink, CrystalData): update the emitted names. See [Names used by generated code](#names-used-by-generated-code).
3. Rebuild. Code generated by TinyhandGenerator is regenerated automatically.

Most renames are safe whole-word replacements. Handle these manually because the old name is also used elsewhere:
`TinyhandReader.Clone`, `TinyhandWriter.Clone`, `TinyhandReader.Reverse`, `HashedString.Load`, `Value_*` (class vs. enum member), `TinyhandConstants.*`.

## Attributes (`Tinyhand`)

| Old | New |
| --- | --- |
| `KeyAttribute.AddProperty` | `KeyAttribute.PropertyName` |
| `KeyAttribute.Alternate` | `KeyAttribute.AlternateKey` |
| `KeyAttribute(int x)`, `KeyAttribute(string x)` | parameter `key` |
| `TinyhandObjectAttribute.LockObject` | `TinyhandObjectAttribute.LockMemberName` |
| `delegate void ByRefFunc<T1, T2>(in T1, T2)` | `delegate TResult ByRefFunc<T1, TResult>(in T1 arg1)` |

Example: `[Key(0, AddProperty = "Name")]` → `[Key(0, PropertyName = "Name")]`, `[TinyhandObject(LockObject = nameof(x))]` → `[TinyhandObject(LockMemberName = nameof(x))]`.

## Names used by generated code

Generators that emit Tinyhand code must use the new names:
`IncrementDepth`, `ReadMapHeaderOrEmptyArray`, `ReadStringConvertible`, `ReadStringConvertibleOrDeserializeAndReconstructObject`, `WriteRaw`, `JournalRecordType`, `WriteKeyRecord`, `WriteValueRecord`, `WriteLocatorRecord`, `ReadKeyRecord`, `ReadValueRecord`, `ReadLocatorRecord`, `IsNextKeyRecord`, `IsNextNonValueRecord`, `ThreadSafeTypeKeyHashtable`, `UnsafeEnumPlaceholder`, `RegisterInterfaceListFormatter`, `RegisterInterfaceCollectionFormatter`, `RegisterTwoDimensionalArray`, `RegisterThreeDimensionalArray`, `RegisterFourDimensionalArray`.

Known impact: ValueLink 0.119.0 emits `DepthStep` and `ReadMapHeader2`, so projects using it do not compile against this version until ValueLink is updated.
