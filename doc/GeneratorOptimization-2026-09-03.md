TinyhandGenerator の生成コードの最適化（2026-09-03）

比較元はコミット `29a5cb4`。生成された Serialize / Deserialize / Clone と、それらから呼ばれる組み込みコレクション処理を確認し、以下を変更した。コメントアウトされたコードは保持している。

- 文字列キーを、MessagePack ヘッダーを含む定数の `ReadOnlySpan<byte>` として生成する。ヘッダーと UTF-8 本体を一度の `WriteSpan` で書き込み、実行時の長さ判定とバッファ操作を減らす。引用符・バックスラッシュ・改行を含むキーも、C# の文字列リテラルを壊さず生成できる。
- 文字列キーの既読フラグをビットで管理する。64 項目までは初期値 0 の `ulong`、それ以上は明示的に Clear した `Span<ulong>` を使う。未初期化の `stackalloc bool[]` への依存をなくし、スタック使用量と要素アクセスを減らす。
- 組み込みのプリミティブ・文字列 List の書き込みを `CollectionsMarshal.AsSpan` 経由にする。各要素で List のインデクサーを通す処理を省く。
- 空配列の読み込み・複製では `Array.Empty<T>()` を使う。組み込み配列の複製では、長さ 0 の `Array.Copy` 呼び出しも省く。非空配列の独立した複製、独自 resolver、深度制限は維持する。
- Nullable の生成コードで、HasValue 確認後の Value 参照に出ていた null 許容性の警告を解消する。

List の読み込みに SetCount と Span を使う案も比較したが、小さい List や構造体 List で遅くなるケースがあったため採用していない。読み込みのアルゴリズムは従来のまま。テンプレート `.tt` と生成済み `.cs` は両方更新した。

測定は Windows 11 / Core i9-13900K / .NET 10.0.11 / BenchmarkDotNet 0.15.8、Release の InProcessEmitToolchain で行った。変更前のジェネレーターとランタイムを別ディレクトリに保存し、同じベンチマークソースをそれぞれの DLL でコンパイルして比較した。ビルドやテストを速度測定と同時に実行していない。

| List<string> 256 要素の書き込み | 1,136.22 ns | 1,107.22 ns | 2.6% | 0 → 0 B |

4 要素の List も測定した。整数 List の書き込みは 7.855 → 7.807 ns で実質同等、文字列 List は 20.29 → 19.73 ns。残る 80 B は配列を保持するオブジェクト本体の割り当てである。文字列キーのモデルは既定値の省略を有効にしており、値は nil として出力されるため、キー処理の割合が大きい。空配列の読み込みデータは nil ではなく空の配列ヘッダーを明示的に含む。

表は各変更を確定した測定結果をまとめたもの。通常はウォームアップ 5 回、測定 10 回、1 回 150 ms。文字列 List はウォームアップ 8 回、測定 15 回で再確認した。短い処理では JIT・GC・OS の影響があるため、ここでの改善率を全データ・全環境の保証とはしない。構造体 List の読み込みでは一度大きなばらつきが出たが、対象を絞った再測定では再現しなかった。

再実行用のベンチマークは `Benchmark/Benchmarks/GeneratedCodeBenchmark.cs` に追加した。


検証結果:

- 回帰テストを 25 ケース追加し、Debug / Release とも全 537 ケース成功。
- キー長 31/32、255/256、65535/65536 バイトの境界、Unicode・特殊文字、65 個以上の既読フラグ、欠落・重複・未知キー、SkipLocalsInit を検証。既存の 512 バイトを超えるキーの警告対象については、書き込むバイト列の互換性を検証した。
- 空・単一・256 要素の List、Nullable 構造体、ジャグ配列、独自 formatter、コールバック、文字列変換、例外時の深度復元、非空配列の独立した複製を検証。
- Roslyn をテスト内で起動し、生成コードのコンパイルと実行も検証。
- ソリューション全体の Release ビルド成功（警告・エラー 0）。
- NativeAOT の publish とネイティブ実行が成功。特殊文字を含む定数キー、List、空配列の読み込み・複製のケースも追加。
- 既存の割り当て量テストで単発の 16 B の揺れを検出したため、同じ 1,000 回の測定を 3 バッチ行い、その最小値を比較するようにした。呼び出しごとの割り当て増加を検出する厳密な比較は維持している。

Debug の行カバレッジは、TinyhandGenerator が 32.85% → 39.41%、Tinyhand ランタイムが 78.30% → 78.36%。ジェネレーターの分岐カバレッジは 26.40% → 32.93%。ジェネレーターの数値はテスト内で実行した経路を示し、通常のビルド中に生成したコードの実行をそのまま計測するものではない。追加したコンパイルテストにより、ArrayCoder は 64.24%、ListCoder は 56.96%、NullableCoder は 75.00% の行を計測できた。全機能の完全網羅には至っていない。
